# Premium with shared Economy and Shop

Inject IBattlePassPremiumAccess; the provided EconomyBattlePassPremiumAccess checks quantity>0 of the snapshot's PremiumEntitlementId. There is no premium boolean in Battle Pass save. Unique entitlement target IDs include a stable authored occurrence. Declare them as unique ResourceRewardDefinition targets at shared-wallet construction. No dynamic target registration API is assumed.

Host publishes one purchaseOnce virtual-currency Shop offer whose ownershipResourceId is the same entitlement; grant that ownership resource once, last in its rewards. With the existing transaction wallet, gem debit and entitlement grant use the shared Economy exchange. Gate navigation/purchase by the expected active occurrence, active time window, no pending operation and no RequiresReload. Reject stale popups after expiry. Call feature Refresh after purchase so old earned Premium slots become claimable.

The sample declares one occurrence in advance, seeds500demo gems with a stable receipt and charges200 through ShopModel.Purchase. Production should merge the offer into its existing Shop catalog and use its existing wallet. Receipt/restore/IAP SDK fulfillment is deferred. No UI sets premium, subtracts gems or manually grants slot rewards.
