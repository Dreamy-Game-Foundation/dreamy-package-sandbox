# Performance controls below banner and complete console details

Completed 2026-11-06, candidate 0.3.0-preview.6. HUD mode controls are the first row of Performance's scrollable `Viewport/Content`, below the header/banner, with 48-unit row height. Original prefab references/GUIDs stay unchanged.

Console intake no longer clips message/stack at 2048/4096 characters. Pending queue and retained history each have a 2 MiB budget; eviction also trims the post-Clear visible buffer. Oversized entries/full queue increment DroppedCount rather than silently clipping. The selected message plus supplied trace is rendered as plain text without the previous 2600-character cutoff. Details longer than 12000 characters have Previous/Next pages, split preferably on newlines and without splitting a UTF-16 surrogate pair. Each page fits a single uGUI Text mesh; Copy retains the full original entry. This preserves what Unity supplies; it does not synthesize omitted stack frames or force expensive global native-stack settings.

92 EditMode + 56 PlayMode passed in an isolated source consumer. Regression coverage checks HUD's content parent, full long-message and 800-frame trace reconstruction, final tail, Copy original data, clearing details, and memory bounds after Clear with large entries. Actual sandbox MCP measured row below banner and verified a 33989-character synthetic trace across four pages with exact full-text reconstruction and final tail. No resource cheats or report delivery were invoked; Editor stopped after inspection. No phone/iOS/build/performance certification is claimed for this follow-up. Test XML and MCP receipts are alongside this file. One fixture initially selected before virtual layout updated; it now waits for the actual row update before selecting.
